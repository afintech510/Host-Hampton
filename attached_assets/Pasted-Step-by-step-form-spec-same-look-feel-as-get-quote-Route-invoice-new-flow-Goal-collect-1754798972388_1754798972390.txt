Step-by-step form spec (same look/feel as /get-quote)
Route: /invoice (new flow)
Goal: 

collect party prefs (no pricing) → Collect & Submit form → Present quote, allow customer to edit party details, allow customer to lock in the date/time (checked against event calendar) & take $200 deposit via Stripe → this should put a new event in the main /admin/calendar, create a new invoice with status as "Deposit Paid", the customer can no longer edit the invoice, but the host hampton manager on the dashboard will have ability to edit / update the invoice up until 7 days before event.
Do not show pricing until after user submits their contact info.
Steps
1.	Theme & Package
•	Fields: Theme (Standard $875 / Custom from $950), Package (None / L1 / L2 / L3 / L4).
•	Package cards show: Price, Value, Savings (calc below), “What’s included” note, “Customize”.
•	Packages (lock these):
o	L1: $350 (value $435) — save $85 (19.5%)
o	L2: $695 (value $935) — save $240 (25.7%)
o	L3: $925 (value $1,310) — save $385 (29.4%)
o	L4: $1,375 (value $2,124) — save $749 (35.3%)
2.	Activities
•	Rule: either “1 premium + 1 standard” or “3 standard” (when no bundle selected).
•	If a bundle is selected, activities contribute their retail value toward the bundle’s value cap until filled; over-cap items price à la carte.
•	Per guest activities multiply by guest count.
3.	Food & Dessert
•	Kids entrée: Standard (Pizza or Bagels) included.
•	Upgrades (flat): e.g., Chicken Fingers & Fries, Adult pies, Specialty pie, Fruit platter, Popcorn bar, Drinks, Coffee bar, Cupcakes variants.
4.	Add ons
•	Flat or per guest items (e.g., Photo Booth, Candy Wall, Karaoke, Balloons, Barbie Box, Goody bags [std/premium], Softplay, Glitter Tattoos, Hair Tinsel, etc.).
•	Any price mismatches vs site/Sheet surfaced later as a “Price Alert”.
5.	Location, Date, Time
•	“Host Hampton” vs “Mobile (enter address)”.
•	Preferred date + selectable time slot list.
•	Note: “Date held after deposit; final confirmation by email.”
6.	Guests
•	Estimated guest count (base includes 10; additional $/guest).
•	Age, birthday child name.
7.	Contact & Notes
•	Host name, email, phone, notes/requests, opt in checkbox copy reused from current form.
8.	Review & Instant Quote
•	Itemized preview (read only here), Taxes estimate, Deposit line, CTA: “Reserve with $200 deposit”.

Pricing engine rules (source: your Sheet; keep as single source of truth)
•	Base Party: Standard theme $875; Custom from $950 (enter actual value you decide in Sheet for each custom theme).
•	Guests: up to 10 included; extra guests add per guest charges for selected per guest items.
•	Activities: per guest or flat as defined in Sheet; enforce activity rules if no package chosen.
•	Food & Add ons: flat or per guest per Sheet.
•	Mobile fee: distance-based placeholder (to be finalized).
•	Packages (bundles):
o	Selecting L1–L4 adds one bundle line at the bundle price and opens a bundle value cap equal to the level’s value.
o	Items added during steps 2–4 draw down the cap at retail (qty adjusted).
o	Over-cap amounts price à la carte.
o	Show a progress meter: “$X of $Y bundle value used.”
o	Savings shown on Review = (retail-in-bundle − bundle price) + avoided overage.
•	Tax: applied to actual charged amounts (local settings).
•	Rounding & display: always show dollars, no trailing .00 if whole.

/invoice experience (objects, routes, permissions)
Routes
•	Customer-facing: /invoice/:id (view + pay).
•	Manager console: /admin/invoices/:id (full edit powers).
•	Creation: successful quote step creates invoice in Draft.
States
•	Draft → Deposit Paid → Finalized → Paid → (optional) Refunded/Voided.
Invoice layout
•	Header: Invoice #, Status chip, Event date/time, Location, Customer info.
•	Lines (editable by manager):
o	Theme base (std/custom)
o	Package Level N (shows Price, Value cap, Included items list with retail subtotal, Savings)
o	Activities (qty ties to guest count if per guest)
o	Food & Dessert
o	Add ons (balloons, booth, etc.)
o	Extra guests (auto)
o	Mobile fee / custom adjustments
o	Discount (optional)
o	Tax (auto)
•	Totals: Subtotal, Tax, Payments (shows $200 deposit as Payment #1), Balance Due.
•	Timeline: quote created → deposit paid (Stripe event) → edits → finalize → balance paid.
Editing after deposit
•	Manager can edit any line item, guest count, swap bundle contents, add over-cap items.
•	Rules: keep the original $200 as a payment record; only the remaining balance changes.
•	If the edit reduces total below $200, balance becomes $0 and show “Credit due or refund options” (manager-only action).
Actions
•	Customer: “Pay $200 Deposit” (if Draft), “Pay Remaining Balance” (if Finalized & deposit paid), Download PDF, Print.
•	Manager: Edit lines, override prices, apply discount, resend links, record offline payment, refund, finalize, lock (read-only) after Paid.
________________________________________
Stripe flow (behavior only)
•	Deposit: Create Checkout Session for fixed $200 with invoice_id metadata. On success: set status → Deposit Paid; mark date as held.
•	Balance: On Finalize, create a Stripe Invoice (recommended) or a new Checkout Session for the remaining balance.
•	Webhooks: checkout.session.completed, invoice.paid, charge.refunded → update invoice timeline & status.

Data model additions (no migrations yet—just schema intent)
•	packages: id, name (L1–L4), price, value_cap, active
•	items_catalog: id, name, type(theme/activity/addon/food), tier(standard/premium|null), pricing_type(flat/per_guest), retail_price
•	quotes (if you keep): id, selections JSON, computed_totals JSON
•	invoices: id, quote_id, customer, event, guest_count, line_items[], bundle_usage {level, value_cap, used, included_item_ids[]}, subtotal, tax, payments[], balance, status, stripe_refs {deposit_session, balance_invoice}, audit_log[]

Edge cases & guardrails
•	Price Alerts: if an item’s price differs between Sheet and site content, show a manager-only flag on /admin invoice view.
•	Bundle overflow: visually call out items that are over-cap (“priced à la carte”).
•	Guest count change: re-run per guest math and bundle usage; prompt if dropping count below items already consumed (e.g., favors qty).
•	Mobile party: require address before Review; show potential travel surcharge placeholder if rules not finalized.
•	Holds: Deposit times out (no payment) → invoice stays Draft; date not held.
